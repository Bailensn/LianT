# 安全模型

## 信任根

- 每个 Service 首次初始化时生成一对 **ECDSA P-256** 身份密钥，私钥只存在服务器
  `data/node` 目录；指纹是 `base32(SHA-256(公钥 DER))`，按 4 位分组显示。
- 配对时这个指纹经二维码交给客户端并**钉住**；换密钥等于换身份，所有设备都要重新配对。
- 每台客户端用自己的 P-256 私钥证明身份，私钥不可导出：
  网页端用 Web Crypto 生成后以 `extractable: false` 存进 IndexedDB。

## 每次连接发生什么

1. TLS 握手：浏览器只能靠 CA 或首次信任，**不能钉证书**。
2. `auth.challenge` 带 `service_pub` 与 `service_sig`：
   客户端先比对公钥指纹与配对时钉住的值，再验签。不一致直接断开。
   这一步把证书钉扎补在应用层——反代、企业根证书、被攻陷的 CA 都冒充不了服务端。
3. 客户端用 `nonce || 服务端指纹 || ts` 签名作为 `auth.response`，服务端用登记的
   设备公钥验签；`nonce` 一次性，重放必败，`ts` 偏差超过 60 秒拒绝。
4. 同一 IP 每分钟最多 5 次失败；设备数量上限默认 8。

## 公网暴露

在设备密钥之外再加一道 HTTP 基本认证：

- `LIANT_BASIC_AUTH=user:pass` 或 `config set auth.user / auth.pass`；
- 认证覆盖网页、`/v1/ws` 握手与媒体下载，浏览器登录后同源 WebSocket 自动复用凭据；
- 用户名与密码都用定长比较；同一 IP 每分钟 10 次失败后返回 429；
- 失败事件写进安全日志，可在设置页看到来源 IP。

它挡的是「知道地址就能打开页面」这类扫描流量，不能替代设备密钥：
拿不到私钥仍然连不上。

## 传输与存储

- 内置模式：TLS 1.3 + 自签证书，只有服务端私钥能完成握手。
- 反代模式：`LIANT_NO_TLS=1`，由 Caddy/Nginx 终止 TLS。
  **代理到容器这一段是明文**，所以只能走 Docker 内部网络，不要把它暴露到公网。
- 配置、密钥、数据库都在数据卷里；容器以非 root、无 capabilities、
  `no-new-privileges`、只读根文件系统运行。
- 网页响应带 CSP、HSTS（TLS 模式）、`X-Content-Type-Options`、`Referrer-Policy`、
  `frame-ancestors 'none'`；不允许内联脚本。

## 已知取舍

- 网页端首次打开需要信任自签证书（或用反代拿正式证书），这是浏览器的限制；
  之后靠上面的应用层自证兜底。
- 媒体下载链接是 HMAC 签名 + 10 分钟有效期，拿到链接的人在有效期内可以下载。
- 配对码 6 位、60 秒、一次性，且必须由服务端终端确认；
  终端确认是防「二维码泄漏即可绑定」的第二道闸。
