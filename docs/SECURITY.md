# 安全模型

## 信任根

- 每个 Service 首次初始化时生成一对 **ECDSA P-256** 身份密钥，私钥只存在服务器
  `data/node` 目录；指纹是 `base32(SHA-256(公钥 DER))`，按 4 位分组显示。
- 配对时这个指纹经配对信息（JSON / 二维码）交给客户端并**钉住**；换密钥等于换身份，
  所有设备都要重新配对。
- 每台客户端用自己的 P-256 私钥证明身份。**v1 的私钥存在本地存储里**
  （Web 为 localStorage，Android/桌面为应用私有目录），**还没有接入
  WebCrypto 不可导出密钥或 Android Keystore**，这是已知缺口：能读到应用数据的人
  就能拿到私钥。服务端只保存公钥。

## 每次连接发生什么

1. TLS 握手：浏览器与原生客户端都依赖系统信任库，**v1 不在客户端做证书钉扎**；
   自签证书需要先被信任，或由反代换成正式证书。
2. `auth.challenge` 带 `service_pub` 与 `service_sig`：客户端先比对公钥指纹与配对时
   钉住的值，再验签。不一致直接断开。这一步把证书钉扎补在应用层——反代、企业根证书、
   被攻陷的 CA 都冒充不了服务端。
3. 客户端用 `nonce\n服务端指纹\nts` 签名作为 `auth.response`，服务端用登记的设备公钥
   验签；`nonce` 一次性，重放必败，`ts` 偏差超过 60 秒拒绝。
4. 同一 IP 每分钟最多 5 次失败；设备数量上限默认 8。

## 公网暴露

可以在设备密钥之外再加一道 HTTP 基本认证：

- `LIANT_BASIC_AUTH=user:pass` 或 `config set auth.user / auth.pass`；
- 认证覆盖 `/v1/ws` 握手、`/v1/media/` 与根路径；用户名和密码都用定长比较，
  同一 IP 每分钟 10 次失败后返回 429；
- 失败事件写进安全日志，可在客户端「设置 → 安全日志」里看到来源 IP。

注意两个限制：

- **当前 Flutter 客户端不会在 WebSocket 握手时带 `Authorization` 头。**
  浏览器如果已经缓存了该源的 Basic 凭据，握手可能自动带上；Android/桌面端则不会。
  启用 Basic 认证前请确认客户端形态，或把访问控制放在反向代理层。
- `auto_pair`（免配对码登记）只在启用 Basic 认证时可用，且只对已经在 HTTP 层
  通过认证的连接开放；普通部署请用配对码。

它挡的是「知道地址就来扫」的流量，不能替代设备密钥：拿不到私钥仍然连不上。

## 传输与存储

- 内置模式：TLS 1.3 + 自签证书，只有服务端私钥能完成握手。
- 反代模式：`LIANT_NO_TLS=1`，由 Caddy/Nginx 终止 TLS。
  **代理到本进程这一段是明文**，只能走回环或容器内网，不要把它暴露到公网。
- 配置、密钥、数据库都在 `data/`；用独立用户运行，systemd 只放开数据目录可写
  （见 `deploy/liant.service`）。
- 根路径与媒体响应带 CSP、HSTS（TLS 模式）、`X-Content-Type-Options`、
  `Referrer-Policy`、`frame-ancestors 'none'`。服务端不再提供 HTML 页面。
- 媒体下载链接是 HMAC 签名 + 10 分钟有效期，拿到链接的人在有效期内可以下载。

## 已知取舍

- 客户端首次连接需要信任自签证书（或用反代拿正式证书）；之后靠上面的应用层自证兜底。
- 客户端私钥没有硬件保护，见「信任根」。
- 配对码 6 位、60 秒、一次性，且必须由服务端终端确认；
  终端确认是防「二维码泄漏即可绑定」的第二道闸。
- 吊销设备后立即不可认证（服务端删公钥），但已经下载到本地的消息不会被远程清除。
