# 界面设计规范（Flutter 客户端）

依据移动端设计惯例（iOS HIG 的留白优先、背景分层、动效克制）与
[Ludi-Herry/mobile-design-system-skill](https://github.com/Ludi-Herry/mobile-design-system-skill)
的六步工作流落地。本文只记录本项目的执行口径，面向 `manager/` 里的 Flutter 客户端：
**Android 是唯一交付目标**，Web 只用于本地预览（不对外发布），不做桌面产品。

## 硬门禁与实现

| 规范条款 | Flutter 落地 |
| --- | --- |
| 顶部避让状态栏/灵动岛 | 页面根节点用 `SafeArea` / `MediaQuery.paddingOf`；大标题页由 `SliverPersistentHeader` 承担吸顶 |
| 底部避让 Home Bar | 悬浮底栏距屏幕底 `16 + MediaQuery.padding.bottom`；输入条用 `SafeArea(top:false)` |
| 软键盘不遮挡输入 | `Scaffold.resizeToAvoidBottomInset`；输入条贴在 `Stack` 底部，键盘弹起时整体上移 |
| 最小触控热区 44×44 | `LTokens.touchTarget = 44`；返回、备注、发送、行内操作都按这个尺寸或更大 |
| 相邻可点项留白 ≥8 | 列表行 `gap: 12`，底栏项之间留 4–8；行高 ≥64 |
| 细分隔线 | 0.5 逻辑像素、颜色 `LColors.sep`（浅色 7% 黑、深色 10% 白） |
| 3–5 槽位底栏 | 会话 / 机器人 / 设置，悬浮玻璃胶囊，选中态品牌色 12% 底 |
| 空态与失败出口 | 每个列表都有空态文案；断线常驻说明条 + 「立即重试」；不拦住已加载内容 |
| 同心圆角 | 卡片 20、按钮 12–16、气泡 18；内层圆角随外层收缩 |
| 单一主 CTA | 配对页只有「直接进入」是全宽主按钮，配对码是次级 |

## 视觉语言

- **背景分层**：`--bg` 页面底色 `#F2F2F7`（深色纯黑），卡片 `#FFFFFF`（#1C1C1E），
  按下态 `#E9E9EE`（#121214）。层级靠背景差，不靠投影；只有悬浮底栏带柔和投影。
- **强调色**：单一品牌蓝 `#2F6BFF`，只用于主按钮、选中态、未读数与链接。
- **文字层级**：34px 加粗大标题（滚动收到 20px）、17px 列表标题、16px 正文、
  13px 次级、11–12px 辅助。文字色只在 `LColors.text / text2 / text3` 三档里选。
- **玻璃**：底栏与聊天头部用 `BackdropFilter(blur 24)` + 卡片色 72% 透明度，
  底下必须有滚动内容；不要铺在纯色背景上。
- **动效**：只在首屏与面板出现时用 180–220ms 的过渡；不做滚动视差、不做循环动画。
- **深浅色**：只跟随系统 `ThemeMode.system`；深色背景纯黑（OLED），卡片提亮一级。

## 结构与页面

- **大标题页**：`LargeTitlePage`，34px 标题随滚动收到 20px 并吸顶，折叠后补 0.5px 底边；
  右侧只放一个轻量动作（状态徽标 / 添加 / 刷新）。
- **会话列表**：搜索框（44 高）+ 按「今天 / 昨天 / 本周 / 更早」分组；
  组内是一张 20px 圆角卡片，行内是头像、标题、时间、预览、未读。
- **聊天页**：玻璃头部随滚动折叠（标题 17→15、隐藏副标题与回复窗口倒计时）；
  群聊在气泡上方显示发送者；时间间隔超过 5 分钟插一条时间分隔；
  气泡最多占宽 78%，出站是品牌蓝、入站是卡片色；底部输入条含模式说明。
- **机器人页**：状态徽标 + 启停按钮 + 移除；添加用底部抽屉，凭据不落客户端。
- **设置页**：服务、指纹、设备、机器人、安全日志、安全、能力、关于分组；
  危险操作（吊销、解除配对）都走二次确认。

## 宽屏（仅 Web 预览）

宽度 ≥768px 时左侧出现 228px 导航、内容限宽 780、底栏隐藏。这套布局只服务 Web 预览
和横屏平板，**不是单独的桌面端产品**；当前没有 Linux/Windows/macOS 构建。

## 抽屉与输入

- 抽屉用 `showLiantSheet`：拖拽条、最高 85vh、内容独立滚动、页脚固定；
- 表单类抽屉不响应遮罩点击（`isDismissible: false`），只能用「取消」或返回键关闭；
- 键盘弹起时抽屉整体上移（`MediaQuery.viewInsetsOf`），输入框不会被盖住；
- 数字类输入用 `TextInputType.number`，地址用 `url`；
- 发送键在输入为空、断线或发送中时禁用，但不禁用输入框本身。

## 新增界面时必须自查

1. 顶部与底部是否避让了安全区？
2. 每个可点元素热区是否 ≥44px？相邻项是否留够间距？
3. 键盘弹起时输入框与主按钮是否仍可见？
4. 分隔线是否 0.5px 半透明？圆角是否内外同心？
5. 空列表、断网、超时是否都有明确文案与操作出口？
6. 一屏是否只有 1 个全宽主按钮？

## 与协议的关系

- 界面只按 `caps` / `constraints` 渲染，不内置平台假设；
  QQ 的「被动回复 5 分钟窗口」由 `constraints.reply_window_s` 驱动，聊天页头部显示倒计时；
  发送策略不再让用户选：普通消息默认主动，引用/@ 时自动被动（长按消息或点用户名可引用/@），
  过期后仍允许发送，但会提示可能失败。
- 「当前活跃 Bot」是客户端本地状态，切换不重连（v1 只做单 Bot 选择，多 Bot 切换在
  机器人页与通知策略里逐步补）。
- 发送默认按 `constraints.can_initiate` 决定主动/被动；会话设置里可以逐会话覆盖，
  覆盖值存本地。

## 自查结果

最近一轮按上面的条目逐条核对，修掉了这些：

- 聊天输入框被 `Center` 吃掉 `maxHeight`，单行被撑到 132，改为按内容自适应
  （单行 44，多行最多 132）；
- 发送、启动/停止、吊销按钮原来低于 44px 热区，已抬高；
- 三级文字对比度不足，统一换成 `text3`（浅色 `#6F6F76`）；
- 配对页原来有两个全宽按钮，现在只有「直接进入」是主 CTA；
- 图标按钮补了 `Semantics` label，键盘用户有焦点；
- 空态、断线、历史拉取失败都有文案与重试出口。

仍然已知的差距：后台通知、媒体离线缓存。
