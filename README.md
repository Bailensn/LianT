# qbot —— 主进程 / 任务进程 + SQLite + 网页管理后台

**所有配置与运营数据都在一个 SQLite 文件里**（规则、违禁词、群、管理员、禁言、黑名单、入群申请、操作日志），
用**网页后台**（可 Nginx/Caddy 反代）或**群内中文指令**管理，不再有 JSON 配置文件。

- **主进程** `qbot`：只发指令（start/stop/status/logs/admin/db…），随时开关都不影响任务进程。
- **任务进程** `qbot __run`：常驻跑业务，全局唯一（靠绑定控制端口做单例），输出写 `.log` 文件。
- **数据** `qbot.db`：SQLite（纯 Go 驱动 `modernc.org/sqlite`，不需要 gcc/cgo）。
- **管理** 网页后台 + 群内指令；网页可反代、带 token 鉴权。

```
┌────────────┐   指令(回环TCP)   ┌──────────────────┐   SQLite    ┌──────────────┐
│ 主进程 qbot │ ───────────────▶ │ 任务进程 __run   │ ──────────▶ │  qbot.db     │
│ 只发指令    │ ◀─────────────── │ 业务+管理端      │ ◀────────── │  规则/禁言…  │
└────────────┘                  └────────┬─────────┘             └──────────────┘
                                         │ HTTP(可反代)
                                         ▼
                                网页后台 admin.html ── 浏览器/手机
```

## 目录结构

```
qbot/
├── main.go                  主进程入口：CLI、交互控制台、进程拉起
├── internal/
│   ├── cfg/                 配置：路径/端口/环境变量/.env/凭据/接口地址（零硬编码）
│   ├── logfile/             日志文件：8MB 轮转 + tail/follow
│   ├── ipc/                 主进程 ↔ 任务进程 指令协议
│   ├── store/               SQLite 存储层（建表/迁移/全部读写）
│   ├── rules/               回复规则引擎 + 违禁词匹配（纯逻辑）
│   ├── qq/                  QQ 接口：消息、网关、群管理（见 docs/qq-group-api.md）
│   ├── bot/                 业务：会话、消息管线、群内中文指令、处置动作
│   ├── admin/               网页管理端（admin.go + admin.html）
│   └── daemon/              任务进程装配（单例锁、生命周期、播种默认规则）
│   └── proc/                后台拉起（setsid / DETACHED_PROCESS）
├── config/.env.example      凭据与路径模板（复制成 .env 就能用）
└── docs/                    反代示例、QQ 群管理接口能力清单
```

> 运行时的 `.env`、`qbot.db`、`qbot-data/`（日志/pid）是**数据不是源码**，生成在"当前目录/可执行文件旁"，
> 全部可用 `QBOT_*` 环境变量覆盖，`qbot path` 可查。

## 快速开始

```sh
# 1) 拉依赖（首次必须，我这边无法代跑）
go get modernc.org/sqlite && go mod tidy

# 2) 编译
go build -trimpath -ldflags "-s -w" -o qbot .

# 3) 配凭据：把 config/.env.example 复制成同目录的 .env，填两行
#    QBOT_APP_ID=你的AppID
#    QBOT_APP_SECRET=你的AppSecret

# 4) 启动（后台、独立会话；首次会自动建库并播种 /ping 规则）
./qbot start

# 5) 打开网页后台（会打印地址与 token）
./qbot admin
```

## 数据都在 SQLite 里

文件默认 `<当前目录>/qbot-data/qbot.db`（`QBOT_DB_FILE` 可改），表结构：

| 表 | 内容 | 在哪管 |
| --- | --- | --- |
| `settings` | reply_all、reply_default、join_auto_approve、admin_token 等 | 网页「设置」 |
| `reply_rules` | 回复规则（匹配方式/内容/回复/优先级/限定群/启用） | 网页「回复规则」/ 群内指令 |
| `banned_words` | 违禁词 + 处置（撤回/禁言秒数/踢出/拉黑/警告回复/严重度） | 网页「违禁词」/ 群内指令 |
| `groups` | 每个群的开关：启用、reply_all、指令开关、群管能否用指令、机器人是否管理员 | 网页「群」 |
| `admins` | 管理员（全局或限定某群，super/admin）→ 决定谁能用群内指令 | 网页「管理员」/ 群内指令 |
| `mutes` | 禁言记录（到期时间、原因、操作人、状态） | 网页「禁言」/ 群内指令 |
| `blacklist` | 本地黑名单（不回 + 尽量撤回；QQ 侧拉黑需白名单） | 网页「黑名单」/ 群内指令 |
| `members` | **机器人自建群名册**（昵称/角色，来自每条消息）→ 支持按昵称下指令 | 自动维护，网页可看 |
| `audit` | 操作日志（谁、在哪个群、对谁、命中什么、结果） | 网页「操作日志」 |

备份/迁移：网页「设置」里有 **导出 JSON 配置**；直接拷 `qbot.db` 也可以（SQLite WAL 模式，拷贝前 `qbot stop` 更稳）。

## 网页管理后台

- `qbot admin` 打印地址（默认 `http://127.0.0.1:28732/`）与 token。
- token 来源：`QBOT_ADMIN_TOKEN` 环境变量 > `.env` 同名项 > 数据库里自动生成（`qbot db`/启动日志里能看到）。
- 带 token 三种方式：`Authorization: Bearer <token>`、`?token=<token>`（会写 cookie）、或 cookie。
- 页面能干什么：总览（机器人在线状态/重连次数/最近操作）、**群消息（聊天室 / 卡片群发）**、回复规则、违禁词、
  群开关、管理员、禁言（含手动禁言/解禁、查询 QQ 侧禁言状态）、黑名单（可勾选"同时踢出"）、
  入群申请（通过/拒绝/拒绝并拉黑）、操作日志、设置、以及手动调 QQ 接口（撤回/踢出/群信息/群成员）。
- **不用记 ID**：所有页面都按群名 / 成员昵称选择；成员名册来自机器人本地 `members` 表（成员发言后自动登记）。
  只有「手动补录一个从未见过的群」时需要群 ID，添加一次后其它页面都按群名选。
- **群名自动补全**：有 QQ「群信息」接口白名单时，打开「群」或「群消息」页会自动补全空群名（每次最多 8 个，避免触发 30 QPM）；
  也可以点「补全群名」。没有白名单时，点群卡片的编辑按钮手动填写。
- **头像**：QQ 机器人接口不返回群头像或成员头像（官方群信息只有群名/简介/人数，成员信息只有昵称/角色），
  管理端按群名/昵称生成稳定的配色首字头像，不依赖外部图片。
- 反代：支持"剥前缀"和"带前缀"两种写法，配置见 [docs/reverse-proxy.md](docs/reverse-proxy.md)。
- 安全：绑到非回环地址却没配 token 时，管理端**拒绝启动**。

### 群消息（聊天室 / 卡片群发）

- 左侧选群，右侧显示机器人本次运行期间见过的最近消息（最多 60 条）；只列出已启用的群。
- 默认以 **QQ Markdown 卡片**（`msg_type=2`）发送：标题 + 正文，正文支持 `**加粗**`、列表、链接、引用；
  也可以切换为纯文本。
- 「模板」提供群公告 / 维护通知 / 活动提醒 / 欢迎语；点消息下的「引用」可以把最近消息变成一条指定消息。
- 群发会写入操作日志（类型「群发」）。主动消息受 QQ 频控：每个群约 20 条/分钟、1000 条/天。
- 最近消息缓存只在任务进程内存里，重启后清空；不展示 openid，成员按昵称显示。

## 群内中文指令（管理员用）

**判定原则：整条消息本身就是这条指令才生效**（不是"句子里出现了指令词"）。所以：

| 会生效 ✅ | 不会生效 ❌ |
| --- | --- |
| `禁言 @张三 10分钟` | `我刚把他踢了` |
| `@张三 禁言 10分钟`（@ 只是条件词，删掉后仍是完整指令） | `今天天气不错，禁言他` |
| `把张三踢了` / `把我禁言 5分钟`（把字结构） | `他踢了`（代词目标必须带 把/将/给/对） |
| `请禁言 @张三` / `帮我撤回`（客套前缀） | `我想看看状态` |
| `状态` / `@机器人 帮助` | `他刚才发的那条 撤回` |
| 引用某人的消息 → `撤回` | `顺便禁言 @张三` |

判定细节：

- **@提及 = 条件词**：开头的 `@某人` 会被剥掉再判断，剩下的整句仍然是指令就算数；`@` 出现在指令后面也不影响（`禁言 @张三 10分钟`）。
- **把字结构**：`把/将/给/对` + 目标 + 动作 = 正常语序（`把张三踢了`、`给我禁言`）；句首光有代词不算（`他踢了` ✗）。
- **客套前缀**：`请 / 帮我 / 麻烦 / 给我` 可以先说，后面必须紧跟指令。
- **闲聊标记**：句首出现 `我/你/他/想/看/了/过/吗/吧/刚/今天/怎么…` 这类口语词，或句首带标点，一律不当作指令（不回复，避免刷屏）。
- **目标定位优先级**：句首显式名字（`把李四踢了`）> `@提及` > 引用消息 > 32 位 openid > 正文昵称（本地名册）> `我/自己`。
- 管理员之外的人说这些词**完全不响应**；管理员说得不完整（例如只发 `禁言`）才会回一句用法提示。

### 撤回：什么都能撤

撤回接口本身和消息类型无关 —— 文字、图片、语音、视频、文件、markdown/ark/embed 卡片都能撤。
机器人能撤的前提是它**见过**那条消息（撤回要消息 ID，而引用事件只给 `ref_msg_idx`，所以靠内存里最近 200 条消息反查）。

| 说法 | 撤哪条 |
| --- | --- |
| 引用任意消息 → `撤回` | 引用的那条（**任意类型**） |
| `撤回`（不引用） | 上一条（不含这条指令本身） |
| `撤回 @某人` / `撤回 张三` | 他最后一条消息（任意类型） |
| `撤回 3条` / `撤回 10` / `撤回 全部` | 批量撤最近几条（上限 20 条） |
| `撤回机器人` / `撤回你` | 机器人自己刚发的消息（**不限 2 分钟**） |

限制（QQ 侧规则，不是本程序限制）：

- **群成员的消息只能撤 2 分钟内的**（超时报 `40064004`，回复里会写清楚）；机器人是群管理员才能撤别人的消息（否则 `40062003`）。
- 机器人**没收到过**的消息撤不了。QQ 默认只在被 @ 时把消息推给机器人；要让机器人看到群里所有消息（从而能撤任意消息），需要平台开"全量消息"权限。
- 网页后台「手动操作」里同样支持：从最近消息里选一条撤回、按条数撤最近 N 条、选成员撤他最后一条。

## 违禁词与处置

命中违禁词（多条命中取优先级数字最小的）后按配置执行：**撤回消息 / 禁言 N 秒 / 踢出 / 拉黑 / 回复警告**，
并写入 `audit`。本地动作先落库立即生效，QQ 侧失败会把原因写进日志、审计和回复里
（例如 `11253 → 该接口仅白名单机器人可用`）。黑名单成员的消息：不回 + 尽量撤回。

## 配置：`.env` 与环境变量

`.env` 只放**凭据与路径/端口**这类启动期配置（业务数据都在数据库里）。
优先级：**进程环境变量 > `.env` 文件 > 代码默认值**，所有 `QBOT_*` 都走这条链（`.env` 是热读的，文件一改下次读取就用新值）。

- **改完即生效**（不用重启，最长 1 秒内）：`QBOT_APP_ID/SECRET`、`QBOT_ADMIN_TOKEN`、`QBOT_ADMIN_PREFIX`、`QBOT_ADMIN_HTML`、各种 `QBOT_*_URL` 接口地址。
- **要 `qbot restart` 才生效**（进程启动时绑定/打开的）：`QBOT_PORT`、`QBOT_BIND`、`QBOT_ADMIN_ADDR`、`QBOT_DATA_DIR`、`QBOT_DB_FILE`、`QBOT_LOG_FILE`、`QBOT_PID_FILE`。
  `qbot reload` 检测到这类改动会提示你重启（例如"`.env` 里端口是 29999，运行中的任务进程在 28731 —— 改端口要 qbot restart 才生效"）。

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `QBOT_APP_ID` / `QBOT_APP_SECRET` | 空（必填） | 机器人凭据，改完保存最长 60 秒自动生效，或 `qbot reload` |
| `QBOT_ENV_FILE` | 自动查找 | `.env` 路径（可执行文件旁 / 当前目录 / 数据目录） |
| `QBOT_PORT` | `28731` | 控制端口（一台机器跑多个机器人时各用一个） |
| `QBOT_BIND` | `127.0.0.1` | 控制端口绑定地址（非回环会在日志告警：等于把控制权给同网段） |
| `QBOT_DATA_DIR` | 当前目录/qbot-data | 数据目录（找不到可写的则退到可执行文件旁 / `~/.qbot` / 临时目录） |
| `QBOT_DB_FILE` | `<数据目录>/qbot.db` | SQLite 文件 |
| `QBOT_LOG_FILE` / `QBOT_PID_FILE` / `QBOT_RUNTIME_FILE` | 数据目录下同名 | 单独指定这三个文件 |
| `QBOT_ADMIN_ADDR` | `127.0.0.1:28732` | 管理端监听地址 |
| `QBOT_ADMIN_TOKEN` | 自动生成 | 管理端 token |
| `QBOT_ADMIN_PREFIX` | 空 | 反代挂载前缀，如 `/qbot` |
| `QBOT_ADMIN_HTML` | 自动查找 | 自定义管理页面文件 |
| `QBOT_CONSOLE=1` | — | 等价 `qbot run`，日志同时打屏（调试） |
| `QBOT_API_BASE` / `QBOT_TOKEN_URL` / `QBOT_GROUP_*_PATH` | 官方地址 | 接口地址，全部可覆盖（沙盒环境改 `QBOT_API_BASE`） |

## 日志

- 位置：`<数据目录>/qbot.log`（`qbot path` 可查），单文件 8MB 轮转，保留 `.1`~`.5`。
- 业务输出（连接、心跳、收消息、命中规则/违禁词、处置结果、QQ 接口返回）全在日志里，不打屏。
- `qbot logs -f` 跟随，`qbot run` 才会同时打屏。

## QQ 侧前提（重要）

1. **把机器人设为群管理员**，否则禁言/撤回他人消息会返回 `40062003`。
2. **踢人 / 拉黑 / 群成员列表 / 群信息**需要 QQ 白名单权限（错误码 `11253`，联系平台运营申请）；
   代码已全部接好，拿到权限即可直接用，拿不到也不影响违禁词撤回/禁言和本地黑名单。
3. 详细能力表与事件字段说明：[docs/qq-group-api.md](docs/qq-group-api.md)。

## Android 保活

**症状**：连上后过一会儿被 QQ 断开（日志里 `software caused connection abort`），回到 Termux 前台又立刻重连。
**原因**：Android 冻结了后台 App（App Standby / Doze / 厂商省电）。冻结时定时器不走 → 心跳断档 → QQ 踢连接。

代码侧已处理：连上立刻先发一次心跳、**心跳断档自检**（迟到超过 `间隔+max(间隔/4,5s)` 就判定被挂起并立即重连，
日志会写明"进程刚被系统挂起过"）、断线退避自动重连。

系统侧：

```sh
pkg install termux-tools && termux-wake-lock     # 最有效：防 CPU 睡眠/冻结
cd /sdcard/qbot && ./qbot start                  # 用 daemon 方式跑，别用 go run
```

- 设置 → 应用 → Termux → 电池 → **不受限制**；ColorOS/OPPO/一加还要：电池 → 应用耗电管理 → **允许完全后台行为**，
  允许自启动，并在最近任务里锁定 Termux。
- 更稳（不受 App 冻结影响）：`adb shell "cd /sdcard/qbot && setsid ./qbot start"`。
- 别用 `go run .`：临时构建目录会被清掉，配置/日志会落到临时目录（程序会警告并优先用当前目录）。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 首次 `go build` 报缺 `modernc.org/sqlite` | 先 `go get modernc.org/sqlite && go mod tidy` |
| 日志 `机器人凭据未配置` | 填 `.env` 的 `QBOT_APP_ID`/`QBOT_APP_SECRET`，最长 60 秒自动生效或 `qbot reload` |
| `qbot start` 说"已经在运行"但行为还是旧的 | 跑着的是**别的位置**的实例：`qbot status` 看启动时间/数据目录，`qbot stop` 后再 `start` |
| 禁言/撤回报 `40062003` | 机器人不是群管理员，去群里设为管理员 |
| 踢人/拉黑/成员列表报 `11253` | 该接口仅白名单机器人可用，需向平台运营申请 |
| 怀疑凭据被编进二进制 | 不会：无 `go:embed`，`config` 常量留空；可 `strings qbot \| grep -c "$(grep '^QBOT_APP_ID=' .env \| cut -d= -f2)"` 验证为 0 |
| 想换机器/迁移 | 拷 `.env` + `qbot.db` + `qbot-data/`（或网页导出 JSON 配置） |

## 从旧版（Reply.json）升级

老版本的 `Reply.json` 如果还在数据目录里，任务进程**首次启动会自动导入**数据库并把原文件改名 `Reply.json.bak`；
之后请一律用网页后台或群内指令管理。仓库里已不再提供任何 JSON 配置模板。
